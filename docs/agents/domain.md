# Domain Docs

How the engineering skills should consume this repo's domain documentation when exploring the codebase.

## Before exploring, read these

- `spec.md` at the repo root
- `docs/adr/` if decisions exist

## Use the glossary's vocabulary

When your output names a domain concept (in an issue title, a refactor proposal, a hypothesis, a test name), use the term as defined in `spec.md` (e.g. Schedule Slot, Time Band, Slot Hold, Equipment Pool, Price Adjustment, Reschedule Cutoff, Ticket, Check-in, No-Show).
